# 役割分担・グループ構成

最終更新: 2026-11-27

マーケティング・アナリティクスは対象外（外部宣伝不要のため）。
各役割は Claude Code のサブエージェントとして `.claude/agents/<name>.md` に定義済み。

## グループ構成

```
統括（メインセッション）
├── A. 設計グループ ……… 何を作るかを決める
│     ├── rules-architect   ルール仕様・判定ロジック設計
│     └── harbor-designer   ビジュアル/UIデザイン
├── B. 実装グループ ……… 作る
│     ├── rules-engine-dev  ルールエンジン実装＋単体テスト
│     ├── display-dev       表示画面（プロジェクター）
│     ├── control-dev       操作画面（コントロールパネル）
│     └── entry-dev         エントリーページ＋GAS
└── C. 品質・運用グループ …… 本番で事故らせない
      ├── qa-reviewer       コードレビュー・ルール検証・E2E
      └── ops-writer        当日マニュアル・セットアップ手順書
```

## 役割と担当モデル

| 役割 | 責務 | モデル | 選定理由 |
|---|---|---|---|
| 統括 | タスク分解・割振り・進捗管理（task.md）・ユーザーとの合意形成 | Opus | 全体の判断と要件の言語化が中心。判断ミスのコストが最大 |
| rules-architect | 企画書ルールを状態遷移・判定順の仕様に落とす。曖昧点の洗い出し | Opus | 連答権の消失条件、ExRボーダー同点除外、Initial7の選択者など境界条件が多く、推論の深さが品質に直結 |
| harbor-designer | 沼津港モチーフのデザインシステム（色・書体・札コンポーネント）と両画面のレイアウト | Opus | 「AIっぽさを避ける」は判断の質が問われる。デザイン重視の要件 |
| rules-engine-dev | 仕様からルールエンジン（純粋関数）とテストを TDD で実装 | Sonnet | 仕様が固まれば定型的な実装。テスト量が多くコスト効率重視。レビューはOpusが担当 |
| display-dev | 表示画面、Window Management APIでの自動投影、演出 | Sonnet | デザイン仕様に沿った実装作業 |
| control-dev | 操作画面（名前/○/×の3行レイアウト、Undo、CSV入出力） | Sonnet | 同上。ただし操作性は harbor-designer が確認 |
| entry-dev | GitHub Pagesのフォーム、GAS、CSV変換 | Sonnet | 小規模・定型 |
| qa-reviewer | 実装レビュー、ルール仕様との突き合わせ、Playwright E2E、Windows/デュアルモニター確認項目作成 | Opus | 本番一発勝負。ルール誤実装を見抜くには深い推論が必要 |
| ops-writer | 初見向け当日マニュアル、GAS設定手順、トラブル対応表 | Sonnet | 平易で正確な文章。手順の網羅性が重要 |
| （補助）定型作業 | ファイル探索、CSVの体裁チェック、リンク切れ確認など | Haiku | 判断を要さない軽作業はHaikuで高速・低コストに |

### モデル選定の方針
- **Opus**: 判断・設計・レビューなど「間違えると後工程すべてが崩れる」所
- **Sonnet**: 仕様が固まった後の実装・文書作成
- **Haiku**: 判断不要の機械的作業
- 迷ったら上位モデルを選ぶ（本番一発勝負のイベントのため品質優先）

## 作業の流れ（依存関係）

1. rules-architect がルール仕様を作る ／ harbor-designer がデザインシステムを作る（並行）
2. rules-engine-dev がエンジン実装（1の仕様に依存）
3. display-dev / control-dev / entry-dev が並行実装（エンジンとデザインに依存）
4. qa-reviewer が各成果物をレビュー（実装の都度）
5. ops-writer がマニュアル作成 → リハーサル

## サイドバー上の役割別セッション（2026-11-27 作成）

各役割は Claude アプリのサイドバーに独立セッションとして作成した（タイトル形式「役割：クイズ大会スコアボード」）。
初回はリポジトリ未作成のため全員「待機」指示。リポジトリ作成後、統括から作業指示を送る。

| セッション名 | 対応エージェント定義 |
|---|---|
| ルール設計担当 | rules-architect |
| デザイン担当 | harbor-designer |
| ルールエンジン実装担当 | rules-engine-dev |
| 表示画面実装担当 | display-dev |
| 操作画面実装担当 | control-dev |
| エントリー実装担当 | entry-dev |
| 検証担当 | qa-reviewer |
| 運用マニュアル担当 | ops-writer |
