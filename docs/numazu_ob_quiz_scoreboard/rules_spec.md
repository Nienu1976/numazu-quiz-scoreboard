## 1. 共通の考え方

### 1.1 イベントソーシング
- 各ラウンド（2Rなら各組、3Rなら各コース）は **「初期状態 ＋ イベント列」** で表す。
- 現在の状態は `state = events.reduce(apply, initialState)` で常に再計算できる。
- 保存するのは **イベント列だけ**（ローカル保存）。PCが落ちても、イベント列から完全に復元できる。
- `apply(state, event) -> state` は純粋関数。乱数・現在時刻を内部で読まない（時刻が要るイベントは時刻をイベントに含める）。

### 1.2 Undo（1手戻す）
- Undo ＝ **イベント列の末尾から「Undo対象イベント」を1つ取り除き、初期状態から再計算**する。
- スナップショットを積む方式（モックの `H.push(JSON.stringify(S))`）と結果は同じだが、イベント方式なら保存・復元・Undoが1つの仕組みで済む。
- Undo対象: ○・×・スルー・封筒選択・点数入力・打ち切り・サドンデス開始・SD内の○×スルー
- Undo対象外: **タイマー操作**（SFの開始・一時停止・再開）。時計は巻き戻さない（§9）。
- **ラウンド確定（finalize）後はそのラウンドのUndo不可**。確定取消は別操作で、**次ラウンドにイベントが1つも無いときだけ**可能（次ラウンドとの不整合を防ぐ）。
- 勝ち抜け・失格・ラウンド終了もUndoで普通に戻る（状態は再計算で得るので特別扱い不要）。

### 1.3 問題の区切り（何をもって「1問」と数えるか）
問題数を数える場面: 問題数上限【暫定 A1】、サドンデスの問題数上限、Fの休み、3R-Cの選択者。

| イベント | 問題が終わるか |
|---|---|
| ○ | 終わる |
| スルー（誰も正解せず次の問題へ） | 終わる |
| × | **【暫定 N1】終わる**（1問につき解答は1人。誤答で問題終了） |

- 設定値 `wrongEndsQuestion`（既定 `true`）。`false`（誤答後も他の人が押せる）の場合、×では問題は終わらず、その問題は ○ かスルーで終わる。
- 本書の例はすべて `wrongEndsQuestion = true` で書く。

### 1.4 入力の原則
- 早押しラウンドの入力は **○(プレイヤー) / ×(プレイヤー) / スルー** の3種が基本。1クリック即確定（requirements §3.3）。
- **在席（play）以外のプレイヤーへの○×は無視**（エンジンは状態を変えずに返す。UI側ではボタンを無効化）。
- ラウンド終了後（`done`）の○×スルーは無視。

## 2. 共通データモデル

TypeScript風の型で示す（実装言語は技術スタック決定後に合わせる）。

```ts
// 参加者（大会全体で1つ）
type Player = {
  id: string;            // cuid 等
  entryNo: number;       // 受付番号
  displayName: string;   // 表示名（表示画面に出す）
  ki: string;            // 卒業期・所属（表示画面に出す）
  realName: string;      // 本名（運営のみ。表示画面に送らない）
  kana: string;          // ふりがな（運営のみ）
  contact: string;       // 連絡先（運営のみ）
  r1Score: number | null;
  r1Rank: number | null; // 1R順位。1..N の「重複なし」の全順序（§5.3）
  plate: 'red' | 'blue' | 'yellow' | 'green' | null;
  absent: boolean;       // 1R欠席【暫定 N9】
};

// ラウンド内のプレイヤー状態（早押し系の共通部分）
type Status = 'play' | 'win' | 'out';   // 在席 / 勝ち抜け / 失格
type Seat = {
  playerId: string;
  seatNo: number;        // 席番（表示・操作画面の並び順。成績で並べ替えない）
  status: Status;
  winOrder: number | null;   // 何番目に勝ち抜けたか（1抜け=1）
  outOrder: number | null;   // 何番目に失格したか
  // ↓ラウンド固有（各章で定義）
};

type Event =
  | { type: 'correct'; playerId: string }
  | { type: 'wrong';   playerId: string }
  | { type: 'through' }
  | { type: 'selectEnvelope'; envelopeId: string }      // 3R-C
  | { type: 'setScore'; playerId: string; score: number } // 1R, ExR p1
  | { type: 'abort' }        // 打ち切り（問題数上限・運営判断）§3.4
  | { type: 'sdStart' }      // サドンデス開始 §4
  | { type: 'finalize' };    // ラウンド確定

// SF のタイマーはイベント列とは別に持つ（Undo対象外）§9
type TimerEvent = { type: 'start' | 'pause' | 'resume'; at: number /* epoch ms */ };

type RoundState = {
  kind: '1R' | '2R' | '3R-A' | '3R-B' | '3R-C' | 'ExR1' | 'ExR2' | 'SF' | 'F';
  unitLabel: string;     // 「第1組」「Aコース」など
  seats: Seat[];
  seatsToWin: number;    // 勝ち抜け枠（2R=6, 3R=4, ExR2=2, SF=2, F=1）
  questionCount: number; // 終わった問題の数（§1.3）
  phase: 'main' | 'needSD' | 'sd' | 'done';
  sd: SuddenDeathState | null;
  finalRanking: string[] | null; // done 時の順位（playerId の配列, 1位から）
  lastAction: string;    // 「直前の操作」表示用の文
};
```

- 表示画面に送るデータは、本名・ふりがな・連絡先を **含めない派生データ** とする（通信設計は別タスク）。

## 3. 共通: 判定・順位・勝ち抜け枠・打ち切り

### 3.1 ラウンド内順位の作り方（done 時）
上から順に並べる:
1. **勝ち抜け者**: 勝ち抜けた順（1抜け → 2抜け …）
2. **在席のまま終わった人**: そのラウンドの判定基準（各章）で並べる。境界に同点があればサドンデス（§4）
3. **失格者**: 【暫定 A7】常に在席者より下位。失格者どうしは **失格が遅い人ほど上位**（outOrder が大きいほど上）

> 例（2R、打ち切りで終了）: 1抜けA, 2抜けB, 在席C(4○0×), 在席D(3○1×), 失格E(1回目の失格), 失格F(2回目の失格)
> → 順位 A, B, C, D, F, E

### 3.2 自動勝ち抜け【暫定 N2】
- **在席者数 ≤ 残り枠** になった時点で、在席者全員を勝ち抜けにしてラウンド終了。
- このときの勝ち抜け順（winOrder）は、そのラウンドの判定基準で並べた順（同点は1R順位。サドンデスはしない）。
- 例（2R、枠6）: 3人勝ち抜け・6人失格・在席3人 → 残り枠3、在席3 → 3人とも勝ち抜け、終了。

### 3.3 枠割れ【暫定 N3】
- 在席者全員が勝ち抜けても枠が埋まらない場合（在席者数 < 残り枠）、**空いた枠は欠員のまま**。失格者を繰り上げない。
- 途中では起きない: 1回の×で失格するのは1人なので、§3.2 を毎イベント後に判定すれば「在席者数 = 残り枠」でちょうど埋まる。
  - 例（枠6）: 勝抜2・在席5（残り枠4）で1人失格 → 在席4 = 残り枠4 → 4人勝ち抜けで充足。
- 起きるのは **開始時点で在席者数 < 枠** のとき（1R欠席・棄権【暫定 N9】や前ラウンドの欠員）。この場合は開始時に全員勝ち抜け、不足は欠員。

### 3.4 打ち切り（問題数上限・運営判断）【暫定 A1】
- 問題数上限は **既定なし**（設定値 `maxQuestions: number | null`）。
- 上限に達したとき、または運営が「打ち切り」ボタンを押したとき（`abort` イベント）、残り枠を **在席者の判定基準順** で埋める。
- 残り枠の境界に同点者がいれば `phase = 'needSD'` にして、運営の「サドンデス移行」操作を待つ。同点が無ければ即 `done`。
- 打ち切りは早押し全ラウンド（2R, 3R-A/B/C, ExR p2, F）共通。SF は時間切れが打ち切りにあたる（§9）。

### 3.5 サドンデスを行う範囲【暫定 N8】
- サドンデスは **勝ち抜け（復活・優勝を含む）を決める境界の同点だけ** で行う。
- 勝ち抜けに関係しない順位（敗者どうしの順位など）の同点は 1R順位で決め、サドンデスはしない。

## 4. 共通: サドンデス

### 4.1 開始条件と対象
- 対象者 = 境界上の同点者全員（n人）。取り合う枠 = K（1 ≤ K < n）。
- 例: 2R打ち切り時、残り枠2、在席者を判定基準で並べると 4○0× が A,B,C の3人で同点の先頭 → n=3, K=2。

### 4.2 ルール
- 形式: **1○1×**。○で即その時点の最上位として枠を獲得、×でサドンデス失格。
- 問題数上限: **参加人数+1問**。参加人数は【暫定 A9】**SD対象者数 n** → 上限 n+1 問。
- 問題の数え方は §1.3 と同じ。

### 4.3 状態
```ts
type SuddenDeathState = {
  players: string[];   // 対象者
  seats: number;       // K
  winners: string[];   // ○を取った順
  losers: string[];    // ×を出した順
  questionCount: number;
  maxQuestions: number; // n + 1
};
```

### 4.4 終了条件（毎イベント後に上から判定）
1. 勝者数 = K → 終了
2. SD内の残り在席数 ≤ 残り枠（K − 勝者数）→ 残り在席者が **1R順位順** に枠を獲得して終了
3. 問題数 = n+1 → 【暫定 A10】残り在席者を **1R順位順** に並べ、上から残り枠を埋めて終了

### 4.5 SD内の順位
勝者（○の順）→ 残り在席者（1R順位順）→ SD失格者（失格が遅い順）。この並びで元のラウンド順位の同点ブロックを置き換える。

### 4.6 例
n=3（A:1R12位, B:1R5位, C:1R30位）、K=2、上限4問
| 問 | 操作 | 結果 |
|---|---|---|
| 1 | スルー | — |
| 2 | C × | C SD失格。在席 A,B=2、残り枠2 → 条件2で A,B が枠獲得、終了 |

別例: 1問目 A ○（A獲得、残り枠1）→ 2〜4問目スルー → 上限到達、在席B,Cのうち1R上位のB(5位)が獲得。順位 A, B, C。

## 5. 1R 100問ペーパー

### 5.1 状態・操作
- 操作: `setScore(playerId, score)`（0〜100の整数【暫定: 1問1点】）。再入力は上書き。Undoも可。
- 欠席者は `absent = true` で順位対象外【暫定 N9】。
- 「確定」は **全員（欠席者以外）の点数が入力済み** のときのみ可能。

### 5.2 順位
- 点数の降順。
- **同点【暫定 A14】**: 1R順位は全ラウンドの最終決め手なので **重複のない全順序** にする必要がある。
  - 既定: 同点は **受付番号の小さい順**。
  - 操作画面で同点ブロック内の順序を運営が手動で並べ替え可能（主催者が別の決め方を指示した場合に対応）。
  - 同点ブロックがある場合、確定前に操作画面で警告表示する（特にプレート境界 5/6・15/16・30/31位）。

### 5.3 プレート
| 1R順位 | プレート | 2R初期○ |
|---|---|---|
| 1–5 | 赤 | 3 |
| 6–15 | 青 | 2 |
| 16–30 | 黄 | 1 |
| 31–60 | 緑 | 0 |

- 参加が60人未満のときも順位の範囲で判定（例: 52人なら31–52位が緑）。

## 6. 2R 連答つき5○2×

### 6.1 構成
- 5組 × 12人、各組 6人勝ち抜け（計30人）。
- 組分け【暫定 A2】: 1R順位の **蛇腹式**。1→1組, 2→2組, …, 5→5組, 6→5組, 7→4組, …, 10→1組, 11→1組 … 。結果、各組 赤1・青2・黄3・緑6。操作画面で手動入替可。
- 席順: 既定は組内の1R順位順。操作画面で変更可。

### 6.2 状態
```ts
Seat (2R) = Seat & { o: number /* ○数 0..5 */, x: number /* ×数 0..2 */ }
RoundState (2R) = RoundState & { holder: string | null /* 連答権保持者 */ }
```
- 初期: o = プレートの初期○、x = 0、holder = null（【暫定 A6】初期○で連答権は付かない）。

### 6.3 操作と遷移
| 操作 | 状態変化 |
|---|---|
| ○(P), P が連答権なし | P.o += 1。holder = P（他人の連答権は消える） |
| ○(P), P が連答権あり | P.o += 2（「連答 +2」）。**holder = null**（連答権は続かない。design_system.md 暫定） |
| ×(P) | P.x += 1。【暫定 A5】P が holder なら holder = null。**他人の連答権は消えない** |
| スルー | 変化なし（**連答権はそのまま**。design_system.md 暫定） |

続けて判定:
- P.o ≥ 5 → P.o = 5（表示は5○で止める）、P.status = 'win'、winOrder 付与。holder が P なら holder = null。
- P.x ≥ 2 → P.status = 'out'、outOrder 付与。
- 勝ち抜け 6人 → done（「第◯組 終了」）。
- §3.2 自動勝ち抜け判定。

連答権の要点（requirements の「自分の正誤・他人の正解で消失」の解釈）:
- 消える: 自分が○（+2を使った）／自分が× ／他人が○
- 消えない: 他人が× ／スルー

### 6.4 境界条件の例（連答権の消失）
組の一部: A(緑0○), B(黄1○), C(青2○)

| # | 操作 | A | B | C | 連答権 | 備考 |
|---|---|---|---|---|---|---|
| 0 | 開始 | 0○ | 1○ | 2○ | なし | 初期○では付かない【A6】 |
| 1 | A ○ | 1○ | | | A | |
| 2 | A ○ | 3○ | | | なし | 連答 +2。権利は続かない |
| 3 | A ○ | 4○ | | | A | 権利なしの正解なので+1、権利を再獲得 |
| 4 | B × | | 1○1× | | A | 他人の×では消えない |
| 5 | スルー | | | | A | スルーでは消えない |
| 6 | C ○ | | | 3○ | C | 他人の○で A の権利は消える |
| 7 | C × | | | 3○1× | なし | 自分の×で消える【A5】 |
| 8 | A ○ | 5○ 勝ち抜け | | | なし | 4→5で勝ち抜け。勝者は権利を持たない |

上限超過の例: C(4○, 連答権あり) ○ → 4+2=6 → **5○に止めて勝ち抜け**。

### 6.5 判定基準（打ち切り時）
○多 → ×少 → サドンデス（境界のみ）→ 1R順位

## 7. 3R

### 7.1 コース選択【暫定 A3】
- 対象: 2R勝ち抜け者（通常30人）。
- 順番: **1R順位の高い順** に A/B/C のいずれかを選ぶ。各コース **定員10**。定員に達したコースは選べない。
- 操作: `chooseCourse(playerId, course)`（順番どおりの人だけ受け付ける）。Undo可。投影で残り枠を表示。
- 枠割れ等で30人未満のときも定員10のまま（最後のコースが少人数になる）。
- 各コース 10人 → 4人勝ち抜け（計12人）。敗者は ExR へ。

### 7.2 3R-A 7up-down
- 状態: `score`（0..7）, `x`（0..2）
| 操作 | 変化 |
|---|---|
| ○(P) | score += 1。score = 7 → 勝ち抜け |
| ×(P) | score = 0、x += 1。x = 2 → 失格 |
| スルー | 変化なし |
- 終了: 4人勝ち抜け、または §3.2。
- 判定基準（打ち切り時）: 終了時の score → SD → 1R順位。失格者は【暫定 A7】常に下位（失格者の score は判定に使わない）。
- 例: A が ○○○○ ×（score 4→0, x1）○○ （score 2）× → x2 失格。

### 7.3 3R-B 7by7
- 状態: `c`（正解P, 初期0）, `w`（誤答P, 初期7）, 得点 = c × w
| 操作 | 変化 |
|---|---|
| ○(P) | c += 1 |
| ×(P) | w −= 1。w = 3 → 失格（4回目の×で失格） |
| スルー | 変化なし |
- **勝ち抜け条件【暫定 N4】: 得点 c × w ≥ 49**（requirements に記載なし。7by7 の一般的な形式に合わせた暫定）。
  - 必要な正解数: w=7→c7(49), w=6→c9(54), w=5→c10(50), w=4→c13(52)
- 判定基準（打ち切り時）: 得点 → 正解P(c) → SD → 1R順位。
- 例: ○○○ ×（c3,w6=18）○○○○○○（c9,w6=54）→ 勝ち抜け。

### 7.4 3R-C Initial7
- 状態: `o`（0..7）, `x`（0..3）, 封筒一覧, 次の選択者 `selector`
```ts
type Envelope = { id: string; questionNo: number; initial: string /* 冒頭の文字【暫定 A11】 */; used: boolean };
```
- 封筒【暫定 A11】: 使用問題すべてを最初から掲示。冒頭文字はCSV事前読込、操作画面で追加・編集可。
| 操作 | 変化 |
|---|---|
| 封筒選択(E) | E.used = true、currentEnvelope = E。選択済み封筒は再選択不可 |
| ○(P) | o += 1。o = 7 → 勝ち抜け。selector 更新 |
| ×(P) | x += 1。x = 3 → 失格 |
| スルー | 変化なし |
- 封筒選択なしでも○×スルーは受け付ける（運用の柔軟性のため。操作画面では「封筒未選択」を警告表示）。

#### 選択者の決め方
1. 1問目: **組（コース）内で1R順位が最上位** の人。
2. 以降: **前の問題の正解者**。
3. 前の問題が誤答／スルーで終わった: **直近の正解者**（＝選択者は変わらない）。
4. 【暫定 N5】選択者になるべき人が勝ち抜け・失格済み: **さらに遡って、在席している直近の正解者**。誰もいなければ **在席者のうち1R最上位**。

実装: `selector = (正解履歴を新しい順に見て最初の在席者) ?? (在席者の1R最上位)`。1問目は正解履歴が空なので後者になる → ルール1と一致。

#### 例（コース内 1R順位: D 3位, E 8位, F 20位, …）
| 問 | 選択者 | 結果 | 次の選択者 | 理由 |
|---|---|---|---|---|
| 1 | D | E ○ | E | 前問正解者 |
| 2 | E | F × | E | 誤答 → 直近の正解者 E |
| 3 | E | スルー | E | 同上 |
| 4 | E | F ○ | F | |
| 5 | F | F ○（7○で勝ち抜け） | E | 【N5】F は勝ち抜け → 遡って在席の直近正解者 E |
| 6 | E | E × （3×で失格） | D | 【N5】正解履歴 F(勝抜), E(失格) → 該当なし → 在席の1R最上位 D |

- 判定基準（打ち切り時）: ○多 → ×少 → SD → 1R順位。

## 8. ExR 敗者復活

### 8.1 phase1 脱落式筆記10問
- 対象: 2R敗者＋3R敗者（通常 30+18 = 48人）。
- 操作: `setScore(playerId, score)`（0〜10）。全員入力で確定可。
- **進出判定（ボーダー同点除外）**: 定員 12。
  1. 得点の降順に、同点者をひとまとまり（グループ）にする。
  2. 上のグループから順に、累計人数が **12以下に収まるグループだけ** 進出させる。
  3. 加えると12を超えるグループに来たら、**そのグループ全員とそれ以下は全員進出不可**。
- 例:
| ケース | 分布 | 進出 |
|---|---|---|
| 要件の例 | 10点2, 9点7, 8点6, … | 2+7=9 ≤12、+6=15 >12 → **9点以上の9人** |
| ちょうど | 10点4, 9点8, 8点3 | 4+8=12 → **12人** |
| 先頭超過 | 10点13, 9点5 | 先頭で13 >12 → **0人**【暫定 A8】 |
| 少数 | 10点1, 9点1, 8点20 | 1+1=2、+20 >12 → **2人**【暫定 A8】 |
- 【暫定 A8】進出者が2人以下（0人含む）: **phase2 を行わず、進出者全員を復活とする。不足枠は欠員**（SF人数が減る）。
- 擬似コード:
```
groups = groupBy(score desc); taken = []
for g in groups: if taken.length + g.length <= 12: taken += g else break
```

### 8.2 phase2 4○1×
- 対象: phase1 進出者（最大12人）。2人勝ち抜け（＝復活）。
- 状態: `o`（0..4）, `x`（0..1）
| 操作 | 変化 |
|---|---|
| ○(P) | o += 1。o = 4 → 勝ち抜け（復活） |
| ×(P) | x = 1 → 失格 |
| スルー | 変化なし |
- 終了: 2人勝ち抜け、または §3.2。
- 判定基準（打ち切り時）: ○多 → SD → 1R順位（在席者は全員 ×0 なので×は基準にならない）。

## 9. SF 7分間タイムレース

### 9.1 構成
- 対象: 3R勝ち抜け12人＋ExR復活2人＝14人 → 2組 × 7人、各組2人が F へ。
- 組分け【暫定 A4】: 1R順位の蛇腹式（1→1組, 2→2組, 3→2組, 4→1組, …）。手動入替可。

### 9.2 状態・操作
- 状態: `score`（整数。【暫定 N6】マイナスあり）, `o`, `x`（表示・参考用）。勝ち抜け・失格は時間中は起きない。
| 操作 | 変化 |
|---|---|
| ○(P) | score += 1 |
| ×(P) | score −= 1 |
| スルー | 変化なし |
- タイマー（Undo対象外、イベント列とは別保存）:
  - `start(at)`, `pause(at)`, `resume(at)`。残り時間 = 420秒 − 経過（一時停止中は進まない）。
  - 【暫定 A12】通常は **一時停止しない**（読み中も時間は進む）。一時停止はトラブル用として操作画面の奥に置く。
  - 残り0 → `timeUp`（表示画面に「タイムアップ」）。

### 9.3 時間切れ【暫定 A12・N7】
- 時間切れの時点で **読み途中の問題は無効**（A12 暫定）。
- 【暫定 N7】時間切れ **前に早押しボタンが押されていた** 問題の解答は有効。そのため `timeUp` 後も運営が「判定確定」を押すまでは ○/× を1回分入力できる（押し込み分）。
- 「判定確定」で判定（§9.4）。以降の○×は無視。

例: 6:59 に A がボタンを押し、7:00 でタイムアップ、7:02 に A が正解 → 運営は ○(A) を入力 → 判定確定。
例: 6:58 から問題を読んでいて誰も押さないまま 7:00 → 無効。運営は何も入力せず判定確定。

### 9.4 判定
- 得点の降順で上位2人が F へ。
- 判定基準: 得点 → SD（2位/3位の境界に同点がある場合のみ）→ 1R順位。
- 例: A 6, B 4, C 4, D 4, … → A 確定、残り1枠を B,C,D のSD（n=3, K=1, 上限4問）。

## 10. F 10○2休

### 10.1 状態
- 4人。`o`（0..10）, `x`（回数。失格はない）, `rest`（残り休み問題数 0..2）
- 休み中（rest > 0）のプレイヤーには○×できない（UIで無効化、残り休み数を表示）。

### 10.2 操作と遷移
| 操作 | 変化 |
|---|---|
| ○(P) | o += 1。o = 10 → 優勝、done |
| ×(P) | x += 1、P.rest = 2 |
| スルー | 変化なし |
- **問題が終わるたびに**（§1.3）、休み中の人の rest を 1 減らす。ただし **その問題で×を出した本人は減らさない**（×を出した問題は休みに数えない）。
- 実装: 問題終了処理で `for p: if p.rest > 0 && p !== 今回×を出した人: p.rest -= 1`

### 10.3 例（A,B,C,D）
| 問 | 操作 | A rest | B rest | 説明 |
|---|---|---|---|---|
| 1 | A × | 2 | 0 | A は2〜3問目が休み |
| 2 | B ○ | 1 | 0 | |
| 3 | B × | 0 | 2 | A の休みが明ける（4問目から解答可）。B は4〜5問目休み |
| 4 | スルー | 0 | 1 | スルーも1問と数える |
| 5 | C ○ | 0 | 0 | B は6問目から解答可 |

### 10.4 全員が休み【暫定 A13】
- 解答可能者が0人のときは、運営が **スルー** を押して問題を進める（読まずに飛ばしてもよい）。休みは通常どおり1減る。
- 例: A,B,C 休み中、D が × → 全員休み → スルーで1問ずつ消化。

### 10.5 判定
- 10○到達者が優勝（1人のみ。done）。
- 打ち切り時【暫定 A1】: ○多 → ×少 → SD（1位の境界のみ）→ 1R順位。
- 2〜4位: 同基準。同点は 1R順位（SDしない【暫定 N8】）。
