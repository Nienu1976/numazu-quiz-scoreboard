## 1. 概要

- 対象: クイズ大会「沼東OB例会 1st」（企画書: 簡易企画書 PDF）
- 作るもの:
  1. **操作画面（コントロールパネル）** … PC側モニターに表示。運営が操作する
  2. **表示画面** … プロジェクターに投影。観客・参加者向け
  3. **エントリーページ** … GitHub Pages で公開。参加者が事前登録する

## 2. 大会ルール（企画書の要約）

共通: サドンデスは原則「参加人数+1」問限定の 1○1×。各ラウンドの最終判定の決め手は **1R順位**。

| R | 形式 | 人数 | ルール要点 | 判定基準 |
|---|---|---|---|---|
| 1R | 100問ペーパー | 60→60 | 順位でプレート付与: 赤1-5位 / 青6-15位 / 黄16-30位 / 緑31-60位 | （順位付けのみ） |
| 2R | 連答つき5○2× | (12→6)×5 | 5○抜け・2×失格。初期アドバンテージ 赤3○/青2○/黄1○。正解で連答権獲得、連答権保持中の正解は2○。連答権は自分の正誤・他人の正解で消失 | ○多→×少→SD→1R順位 |
| 3R-A | 7up-down | 3コース計 (10→4)×3 | ○+1、×で0に戻る。7点抜け、2×失格 | 終了時得点→SD→1R順位 |
| 3R-B | 7by7 | 〃 | 正解P初期0・誤答P初期7。○で正解P+1、×で誤答P-1。得点=正解P×誤答P。誤答Pが3で失格 | 得点→正解P→SD→1R順位 |
| 3R-C | Initial7 | 〃 | 問題冒頭数文字の封筒を掲示、選択者が選んだ問題を出題。選択者: 1問目は組内最上位、以降は前問正解者（誤答/スルー時は直近の正解者）。7○抜け、3×失格 | ○多→×少→SD→1R順位 |
| ExR p1 | 脱落式筆記10問 | 敗退者48→最大12 | 上位12人が進出。**ボーダー上の同点者は全員進出不可**（例: 10点2人・9点7人・8点6人 → 9点以上の9人のみ） | 得点 |
| ExR p2 | 4○1× | 最大12→2 | 4○で復活、1×失格 | ○多→SD→1R順位 |
| SF | 7分間タイムレース | (7→2)×2 | ○+1/×-1、7分終了時上位2名 | 得点→SD→1R順位 |
| F | 10○2休 | 4→1 | ○+1、×で2問休み。10点先取で優勝 | ○多→×少→SD→1R順位 |

人数の流れ: 1R 60人 → 2R 勝抜30 → 3R 勝抜12 ＋ ExR 復活2 → SF 14人 → F 4人 → 優勝1

## 3. 決定事項

### 3.1 運用環境
| 項目 | 決定 | 理由・補足 |
|---|---|---|
| 開催形態 | **オフライン** | 会場ネット非依存 |
| 本番PC | Windows（想定）。開発は Mac | 両OSで動くWeb技術で作る |
| 画面構成 | デュアルモニター。PC側=操作画面、プロジェクター=表示画面 | |
| プロジェクター自動投影 | Chrome/Edge の **Window Management API** で外部ディスプレイを検出し、表示画面を全画面で開く | 初回のみブラウザの許可が必要。失敗時は手動で移動する手順を用意 |
| 画面間通信 | 同一PC内の BroadcastChannel ＋ ローカル保存 | サーバー不要 |
| オフライン起動 | GitHub Pages で公開＋PWAとしてインストール | 当日はネット不要 |
| 画面比率 | 16:9 基準、4:3等でも崩れないようスケーリング | |

### 3.2 エントリー
| 項目 | 決定 |
|---|---|
| 方式（提案・未確定） | GitHub Pages の自作フォーム → Google Apps Script → Google スプレッドシート → 開催前に CSV 書き出し → 操作画面で読み込み |
| 収集項目 | 氏名（本名）、表示名（ハンドルネーム）、卒業期・所属、ふりがな、連絡先 |
| 表示画面に出す | **表示名＋卒業期のみ** |
| 運営のみ | 本名・ふりがな・連絡先（表示画面への送信データに含めない） |
| 予備 | 当日の飛び入りは操作画面から手動追加・編集可 |
| トレードオフ | 初回に Google アカウントでの GAS 設定が必要（手順書を用意）。定員締切は GAS 側で件数判定 |

### 3.3 得点入力（操作画面）
- 早押し機とPCは**連携しない**。運営が手入力
- ペーパークイズ（1R, ExR p1）は**点数を手入力**
- 早押しラウンドのレイアウト（**ユーザー指定**）:
  - 1行目: 参加者（席番号・表示名・卒業期・現在の状態）
  - 2行目: ○ボタン
  - 3行目: × ボタン
  - **1クリックで即確定**（2段階操作は採用しない）
- 並び順: **プロジェクター画面の並び順（席順）と同一で固定**。成績で並べ替えない
- 席順はラウンド開始前に操作画面で決め、両画面に反映
- 押せない状態を明示: 勝抜・失格者は無効化、Fの休み中は残り休み数を表示し無効化
- ラウンド固有状態は名前行に表示（連答権、正解P×誤答P、次の選択者など）
- 誤操作対策: 「1手戻す」を常時大きく表示、直前操作を表示
- 補助ボタン: スルー、サドンデス移行
- 最大14人程度が横スクロールなしで収まること
- 初見でも操作がわかること（最重要の非機能要件）

### 3.4 組分け・選択（すべて暫定）
| 対象 | 暫定ルール | 備考 |
|---|---|---|
| 2R 組分け | 1R順位の**蛇腹式**（1→1組…5→5組, 6→5組…） | 各組 赤1・青2・黄3・緑6 になる。操作画面で手動入替可 |
| SF 組分け | 1R順位の蛇腹式 | 手動入替可 |
| 3R コース選択 | 2R勝抜30人が**1R順位の高い順**に選ぶ。定員10で締切 | 30人共通の順位は1R順位しかないため。投影で残り枠表示 |
| 3R-C 封筒 | **使用問題すべて**を最初から掲示 | 枚数に応じグリッド自動調整。出題済みは「済」表示 |
| 3R-C 封筒文字 | CSV事前読込（問題番号＋冒頭文字）。操作画面で追加・編集可 | |

### 3.5 デザイン
- 軸: **沼津港・海**
- 禁止: 楕円、グラデーション、決まりきったフォント（「AI作成っぽさ」の排除）
- 方向性:
  - 色: 駿河湾の深い藍、船体ペンキの赤・白、錆、ロープの生成り。フラット塗り
  - 形: 競り札、魚箱の文字、港の番号標識、黒板。直角基調
  - 文字: 札・看板風の力強い和文＋角ばった数字書体
  - 得点表現: 競りの値札を差し替えるような「札めくり」演出
- 操作画面もデザイン重視（表示画面と同じ世界観で、操作性を損なわない）
